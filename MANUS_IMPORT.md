# Manus import and hosting handoff

Import this GitHub repository as the source of the existing approved site. Preserve all four pages, links, filenames, local images, local fonts, JS interactions, responsive rules, and precomputed Japanese BudouX spans. Do not redesign, summarise, translate, rebuild in another framework, compress images, or replace assets as part of import.

## Static deployment settings

- Node.js: 22 or later.
- Install: none required. `npm ci --ignore-scripts` is optional; the root package has no third-party runtime dependencies.
- Verify: `npm test && npm run verify`.
- Build: `npm run build`.
- Publish directory: `dist`.
- Default entry: `index.html`.
- Keep `about.html`, `stores.html`, and `reservation.html` as real files at the same directory level.
- Do not force all URLs to a single-page-app route.
- Preserve case, spaces in asset filenames, relative links and UTF-8 encoding.
- Serve `.svg` as `image/svg+xml` and `.woff2` as `font/woff2`.

If importing with a ZIP, extract the contents so `index.html` is at the project root, not under an extra nested directory. GitHub's autogenerated source ZIP may contain a single repository directory; select that directory as the root.

## Before publishing

1. Run `npm test` and `npm run verify` on the unchanged checkout. All hashes must match.
2. Run `npm run build`. The build independently verifies that every production file is a byte-identical copy.
3. Open all four pages and test the language toggle, navigation, mobile menu, gallery arrows/dots, and hover effects.
4. Check that photos, full restaurant logos, chili header mark, local fonts, artwork, and map load.
5. Confirm that the header shows the chili mark beside the company name, and the home store card and store-details panel use the supplied full store logo.

BudouX is already applied to the four scoped Japanese home paragraphs. The pinned parser/model and generator remain in the repository for future edits. They are not downloaded at deployment or called through an external service.

Google Maps and destination booking/delivery services need internet access; their live content cannot be frozen by copying the website code. No owner-private contact details or sales data should be introduced during import.

If the site changes intentionally, review those changes, regenerate the scoped segmentation if needed, then regenerate `SHA256SUMS.json` using `npm run integrity`. Do not regenerate checksums merely to hide an unexplained import mismatch.
